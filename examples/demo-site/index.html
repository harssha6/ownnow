How it works

Three calls. Never half-live.

The same flow agents already know from here.now. A site goes live only when finalize succeeds.

01 / Create

Declare the site

The server reserves a slug like bright-canvas-a7k2 and returns signed upload URLs.

02 / Upload

Files go direct

Bytes go straight to your storage over presigned URLs. They never pass through the server.

03 / Finalize

Flip it live

One atomic switch publishes the version. Every version is kept, so rollback is a pointer flip.

Self-host

Bring your own infra.

Pick where it runs. Every path serves the same sites from storage you control.

Auth model

        

          
Deliberately boring.

          
One bearer key guards publishing. You generate it. No accounts, no hosted control plane, no telemetry. Nothing phones home.

        

      

      

        
One static binaryGo stdlib only. Even S3 request signing is hand-rolled.

        
Your storageLocal disk, or any S3-compatible store. R2 is first-class.

        
Your domainPath URLs by default, or {slug}.your-domain with wildcard DNS.

      

    

  


  

    

      

        
Included

        
What a static host should do.

      

      

        
Versions & rollback
Every publish is immutable. Roll back to any of them.

        
Password sites
Lock a site behind a password with one flag.

        
Expiring sites
Set a TTL. Anonymous publishes expire in 24 hours.

        
SPAs & 404s
SPA fallback, custom 404.html, and directory listings.

        
Wasm & games
Correct application/wasm plus COOP and COEP headers.

        
Agent skill
Claude, Cursor, and other agents can publish to your instance.
